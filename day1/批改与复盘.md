## 三、代码检查

### demo1.java（236 行，§1.1–§1.10 跟敲）— 编译 ✅ 运行 ✅

**做得好的**：把整部分从头敲完，注释是**自己写的理解与预测输出**，不是抄讲义；主动设计对照实验（`char` vs `String` 加法、短路 vs 非短路、switch 两种写法、`Arrays` 全套方法、不规则数组）；`Random(67)` 固定种子让输出可复现；`printf(Locale.US, ...)` 避免本地化干扰。这是本次最有价值的产出。

**需要修正的认知 / 习惯**：

1. `System.out.println(arr1)` 输出 `[I@72ea2f77` —— **Java 数组没有重写 `toString()`**，打印的是 `类型@哈希`。你后面用了 `Arrays.toString`，说明是刻意试的，建议把「为什么是这个」补进注释（这正是期末填空题考点）。
2. `Scanner` 那段实跑输出是 `1020 / 3.14 / 6.28 / hello`：`next()` 已经把 `3.14` 当字符串消费了，`nextDouble()` 读到的是 `6.28`。**Scanner 按 token 消费、不按行**；如果本意是把 3.14 读成 double，顺序就错了。
3. `r.nextDouble(2.0)` 是 JDK 17 `RandomGenerator` 的 `nextDouble(bound)`，含义是**返回 [0, 2.0) 的随机 double**，不是「保留 2 位小数」。实跑 `1.5609...`。
4. `do-while` 那段复用了 while 里已经减到 0 的 `i`，输出 `5->4->3->2->1->0->1->2->3->4->`。逻辑没崩，但要留意**变量状态会跨循环延续**；建议给这段补一行预期输出注释。
5. 术语：「自动 for」规范说法是**增强 for / for-each**。
6. 命名规范：类名 `demo1` 建议 `Demo1`（大写开头），方法 `Add / Say / Function1 / Fact / AddAll` 应为 **lowerCamelCase**（`add / say / fact`）。Java 社区强约定，读别人代码时靠这个判断「这是方法还是类」。public 类名与文件名一致这点你做到了 ✅。
7. 顺手一试：`Fact(13)` 就会 int 溢出，这是第 3 部分包装类 / BigInteger 的引子。

### demo3.java（52 题综合设计）— 编译 ✅ 运行 ✅，但输出暴露 3 个 bug

实跑输出：
```
the student score table: 90 45 77 85 31
the averge is 65                 ← 实际 65.6
the max score is 90
the student score table: 90 77 85 0 0     ← 多了两个 0
```

| # | 问题 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 平均分 `65` 而非 `65.6` | `int total / score.length` **整数除法**丢精度 | 返回 `double`，用 `(double) total / score.length`，`printf("%.2f")` |
| 2 | `90 77 85 0 0` | `RangeOfScore` 返回 `new int[score.length]`（长度 5），只填了 3 个，剩下是默认值 0 | `return Arrays.copyOf(range, count);` |
| 3 | 潜在的数组越界 | `AddScore` 里 `score[count++]` 没检查 varargs 是否超过数组长度 | 加 `if (count >= score.length) break;` 或返回实际写入个数；另外 `boolean` 恒返回 `true` 没有意义，改 `void` 或返回 count |

其他：`averge` 拼写应为 `average`；`CalculateMax` 的 `max = 0` 隐含「成绩非负」假设，用 `score[0]` 更稳妥；题目要的「**按分数段统计**」你实现成了「筛选某区间」，建议补一个 `buckets(int[] a)`，用 `b[Math.min(v / 20, 4)]++` 统计五档人数（注意 100 分要用 `Math.min` 防越界，参考答案里就是这个点）。

### 劣势（高度集中，只有两条主线）

> **诊断：7 道客观错题里，4 道来自「把 C 的规则套到 Java」，3 道来自「引用 / 值传递」，另加 43 题的 JVM 概念混淆。你不是 Java 语法没学会，是两块心智模型还没换过来。**

**主线 A：C 语言经验负迁移**（6、8、28、45，外加 43 一半）
- `char` 1 字节 ASCII → Java 是 2 字节 UTF-16；
- `include/define` 当关键字 → 那是 C 预处理器；
- 「字符串就是 char 数组」→ Java 的 `String` 是**不可变对象**；
- Java 没有 unsigned、没有指针运算（28 漏选 A）；
- `if` 必须是 boolean 的意义，不是「避免死循环」，而是杜绝 `if(x=1)` 与 0/非0 歧义。

**主线 B：值传递 / 引用副本 / 对象可变性**（21、37、42、46，连带 52）
- 这是**最要命的一条**，因为它正好卡在第 2 部分（面向对象）的入口。
- 正确模型一句话：**Java 只有值传递；引用本身也是值。** 传参复制的是「地址」，所以 ① 两个引用指向同一堆对象 → **能改对象内容**（21 漏选的 D、36 你做对的 `int[] b=a`）；② 让形参指向新对象 → **不影响实参**（37 的 `t = t + "c"`）；③ 增强 for 的变量是**元素副本**（42）。
- 用你自己写对的那段 `int[] b = a; b[0] = 9;`（36 题 ✅）反推：`String` 之所以改不动，不是「引用传不进去」，而是 **String 不可变 + 形参重新赋值**两件事叠加。把这两件事拆开，21/37/42/46 一起就通了。

**支线 C：边界、精度与概念术语**（35、43、47、52、51 空题）
- `break outer` 当成 `continue outer`（35）；
- `java` / `javac` / `javap` / `JVM` 四者职责混淆（43）；
- 编程题缺 `n<2` 边界、整数除法丢精度、返回数组残留默认值 0（47、52）；
- 51 题（重载 vs 重写）空着 —— 这题是第 2 部分的预告片，不能跳过。
